# 第一章两次修复复盘

**范围**：`src/index.html` 中“第一章 · 函数·极限·连续”详情页  
**目的**：记录本次页面显示与内容同步问题的排查过程，作为后续维护同类单文件 HTML 内容页的检查清单。

---

## 一、问题一：详情页 Tab 内容嵌套，切换后显示异常

### 现象

- 第一章详情页的五个 Tab（知识地图、七种未定式、方法汇总、连续、速查总表）无法稳定地按独立区域显示。
- 某些 Tab 的内容会被包含在“知识地图”区域中，造成切换后的高度、布局和可见性异常。

### 已确认根因

`buildFunctionDetail()` 中的 `mapBody` 打开了“知识地图”对应的 `.detail-section`，但在与其余四个 Tab 的内容拼接前没有关闭该容器。后续的 `limit1Body`、`limit2Body`、`contBody`、`summaryBody` 因而成为第一个 Tab 的后代节点，而不是同级 Tab 节点。

### 修复

在返回详情内容时先关闭 `mapBody` 的外层容器，再拼接其余 Tab：

```js
body: `${mapBody}</div>` + limit1Body + limit2Body + contBody + summaryBody
```

### 经验沉淀

1. **动态拼接 HTML 时，结构完整性比样式更先检查。** CSS 的 `display: none` / `display: block` 无法修复错误的 DOM 父子关系。
2. **Tab 的每个面板必须是同级 `.detail-section`。** 这是 `switchTab()` 以 id 切换面板的基础约束。
3. 不要仅凭页面“看起来有内容”判断 Tab 正常；应检查 `#detail-body > .detail-section` 的直接子节点数量和 id。

### 建议检查项

```js
const sections = document.querySelectorAll('#detail-body > .detail-section');
console.assert(sections.length === 5);
```

新增或拆分 Tab 时，同步检查：

- 每个模板字符串内的开闭标签是否成对；
- 每个 Tab 面板是否为 `#detail-body` 的直接子节点；
- 切换后目标面板是否为 `display: block`，且 `clientHeight > 0`。

## 二、问题二：知识地图末尾与 3.5 内容不规范

### 现象

1. 知识地图最后的“1.5 反函数求解四步走”和“分段函数反函数”视觉层级不清晰，与前文公式卡片的阅读节奏不一致。
2. 单调性公式曾直接显示 `$$...$$`，没有转化为 KaTeX 公式。
3. “3.5 高频：已知极限存在 · 反求参数”的 B 情形与 `notes/01-函数、极限、连续.md` 不一致，页面使用了双参数例题，缺少笔记中的单参数推导与验证。

### 修复

#### 1.5 反函数：建立明确的纵向学习流

- 用全宽 `.chapter-flow-card` 承载 4 个步骤；
- 每一步使用独立的行，不依赖前后公式网格的列数；
- 将“提公因子反解”拆为独立的全宽例题卡；
- “分段函数反函数”仍使用既有 `memoryBox()`，保持全站提示信息的统一样式；
- 小屏下将步骤标签和正文自动改为单列，避免挤压。

这次不是引入新的通用组件，而是在原有 `formula-card` 体系上补充局部布局类，控制改动范围。

#### 单调性公式：降低动态渲染复杂度

原先将带 `cases` 的显示公式直接插入动态生成的详情 DOM。实际页面出现原始分隔符时，不能把“源码里有 `$$`”当作“公式一定可见”。现已改为三段稳定的行内 KaTeX：

```html
\(x_1 > x_2\) 时：\(f(x_1) > f(x_2)\) 为递增；
\(f(x_1) < f(x_2)\) 为递减。
```

这既保留数学含义，也避免复杂分段公式在动态注入、延迟渲染场景下失效后暴露原始标记。

#### 3.5：以笔记为单一内容源

页面已恢复为笔记中的 B 情形：

```text
已知 lim(x→1) (x² + ax - 2) / (x - 1) = 3，求 a。
```

完整呈现以下步骤：

1. 分母趋于 0 时，为使有限极限存在，分子也必须趋于 0；
2. `1² + a·1 - 2 = 0`，得到 `a = 1`；
3. `x² + x - 2 = (x + 2)(x - 1)`；
4. 约分后极限为 `3`，完成验证。

### 经验沉淀

1. **展示内容和知识笔记发生冲突时，笔记是事实来源。** 不要为页面“补充”一个看似更复杂但未在笔记中维护的例题。
2. **数学公式必须在浏览器中验收。** 检查 `.katex` 节点是否生成，以及是否仍有可见的 `$$`、`\\(` 等原始分隔符。
3. **教育内容优先按学习步骤排版。** 算法步骤、例题和记忆提示是不同层级，不应为了填充栅格而并排混放。
4. **复杂公式逐步降级。** 若显示公式不稳定，优先拆成多个可验证的简单公式，而不是继续堆叠更复杂的 LaTeX 环境。

### 建议检查项

```js
const section = document.getElementById('fn-map');
console.assert(section.querySelectorAll('.katex').length > 0);
console.assert(!section.innerText.includes('$$'));
```

内容同步时，按以下顺序执行：

1. 从 `notes/` 中精确定位对应标题；
2. 对照页面的题目、条件、推导、答案和验证；
3. 只补充笔记中存在的信息；
4. 在浏览器中检查长内容是否完整显示，而不是只检查 DOM 文本。
